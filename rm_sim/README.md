# RoboMaster 云台 / 移动靶仿真（MuJoCo）

一套用于**自瞄视觉算法开发与验证**的 RoboMaster 仿真环境：真实车辆模型 + 物理弹道 + 可交互云台，
并向 YOLO 类检测器提供 **MJPEG 视频流 + 逐帧标注真值**。

配合上级目录的 [`sp_vision_25`](../sp_vision_25)（同济 SuperPower 自瞄框架）使用。

---

## 1. 它解决什么问题

自瞄算法的调试长期依赖实车或场地，存在三个绕不开的痛点：

| 痛点 | 本仿真怎么解决 |
|---|---|
| 装甲板转速、移动方式**无法精确复现** | 靶车的自转周期、急停/冲刺时长、路线全部脚本化，可复现、可扫参 |
| 命中判定的**真值拿不到** | 每帧输出 4 块装甲板的像素级 bbox + 类别（`/state.json`） |
| 训练数据**人工标注成本高** | 视频流与标注同源产生，可直接落盘成数据集 |

目标场景：先在仿真里把"识别 → 跟踪 → 决策 → 开火"整条链路跑通、调参，再上实车。


## 5. 模型转换流水线

源模型：`~/rm-bevy/bevy_robomaster_simulator-master/assets/vehicle.glb`（28 MB，AGPL-3.0）。

```
vehicle.glb
   ├─ 按树分支拆件 ─→ BASE（底盘/4 块装甲板） + GIMBAL（云台）
   ├─ 上轴修正      glTF Y-up → MuJoCo Z-up（rot_x 90°）
   ├─ 定炮管方向    见下方"关键结论"
   ├─ 整车绕 z 旋转 使炮管水平投影对齐 +X（MuJoCo 惯例）
   ├─ 求枢轴        yaw 轴取云台底座重心、pitch 轴取炮口高度
   ├─ 贴纸          沿用源模型自带图案（白字 + 近黑装甲板 + 蓝 LED）
   ├─ 材质取色      按各桶内面数加权的主导材质 baseColorFactor
   └─ 导出          9 个 OBJ + MJCF + manifest.json
```

### 关键结论（踩过的坑，写下来避免重走）

1. **射向不是节点的 +X**。它由 bevy 源码定义：
   `projectile.rs` 里 `direction = (gimbal.rot * launch_offset.rot) * Vec3::Y`，
   而 `setup.rs:192` 把 `InfantryLaunchOffset` 挂在 GLB 的 **`SHOT_DIRECTION`** 节点上
   → 射向 = 该节点的**局部 +Y 轴**（glTF `(0, 0.423, -0.906)` → MuJoCo `(0, 0.906, 0.423)`）。
   换算过来是"朝 +Y、上仰 25°"，正好对应那根 15 mm 细管；+X 极值处其实是 4.7×6.4 cm 的粗方块。

2. **源贴纸的面法线全部朝内**。MuJoCo 双面渲染所以它不会消失，但光照按背面算 → 整片渲染成黑，
   看起来像"没有贴纸"。只需**反转面绕序**，不要动几何（把贴纸"翻到外侧"或"推离板面"都会更糟）。

3. **第 4 块装甲板的贴纸是单字符命名**（`2/3/4/5/B/G/O`，而不是 `13/23/33`）。
   按 `node[1] == 槽位` 过滤会漏掉它，7 片全被当成底盘几何塞进底盘桶。

4. **模型没有纹理**（`MAT_COLOR` 是 128×128 纯白），外观全在 23 个材质的 `baseColorFactor` 里，
   所以按材质自动取色，而不是手编颜色。

## 6. 仿真里已经建模的"真实性"

| 项 | 取值 | 来源 |
|---|---|---|
| 弹丸 | 17 mm / 3.2 g / 25 m/s | 源仓库 `config.toml` |
| 弹道 | **只有重力**（默认）：1 kHz 半隐式 Euler + CCD。**空气阻力**与**自旋（马格努斯）**都已实现但**默认关**（`configs/ballistics.yaml`）：打开阻力后 8 m 落点低 6.5 cm；打开自旋后 8 m 横漂 **15.8 cm**、10 m **25 cm**（∝ d²）—— 后者才是"弹道会飘"的主因（详见 `rm_ballistics.py` 与 §10 验证行） | 本仓库 |
| 云台俯仰限位 | −20.1° ~ +25.8° | 同上（`gimbal_pitch_limit`） |
| 云台安装仰角 | +25°（写进 muzzle site 的 quat） | 源模型 `SHOT_DIRECTION` |
| 底盘尺寸 | 0.518 × 0.494 × 0.231 m | 实测网格 |
| 装甲板 | 0.141 × 0.130 × 0.051 m，四向 | 实测网格 |
| 麦轮半径 / 轴距 | 0.076 / 0.18 / 0.15 m | `config.toml` |
| 靶车自转 | ω ∈ [1.62, 7.02] rad/s，**周期随机 1.2~2.0 s** | 可调 |
| 靶车平移 | 冲刺 1.82~2.52 m/s（3508 同时自转+平移的实际能力） | 可调 |
| 地形起伏 | ±8 cm 高度场，坡度中位 2.30° / 最大 4.75° | 正弦叠加生成 |
| 车身姿态 | 跟随地形法向，跟随误差均值 0.23° | 姿态伺服 |

### 靶车运动（"尽可能难瞄"的设计）

- **自转**：转速按正弦变化，但**每个周期重抽周期**（1.2~2.0 s），用相位累加器保证相位连续不突跳。
  波形做了整形：`ω = (base−amp) + 2·amp·[0.5(1−cos φ)]^q`，`q=0.45` 让低谷停留从周期的 34% 压到
  **13.6%** —— 刚被瞄准就立刻加速转起来。
- **平移**：随机"急停 / 冲刺"状态机，每次冲刺**重抽目标点**（方向突变），起步与刹车受
  加速度限幅（6 m/s²）、转向受角速度限幅（3.8 rad/s），不会出现瞬移。
- **车体升降（轮腿，负责人 2026-10-14）**：四块装甲板整体上下移动，行程 **0 ~ +300 mm**
  （半幅 150；下沿固定为「贴地姿态」—— 单刚体模型再往下就是嵌地，负责人实测发现过）、
  一个完整升降约 2 s，**约 40% 的时间在动**（活动窗口 1~2 个周期 + 静止窗口 2.5~5 s）。
  与自转/平移叠加，是**竖直方向第一个真实的预测误差来源**。四种带升降的靶型
  （固定 / 左右移动 / 原地旋转 / 随机旋转移动升降靶，见 rm_car_script.MODES_LIFT）
  进基准预设 benchmark_2026_lift。细节、边界与核对记录见 configs/README.md。

## 7. 给 YOLO / 检测器的接口

`rm_stream.py` 提供三个 HTTP 端点：

| 端点 | 内容 |
|---|---|
| `/stream.mjpg` | MJPEG 流（`cv2.VideoCapture` 可直接读） |
| `/frame.jpg` | 最新单帧 |
| `/state.json` | 当前状态 + **装甲板标注真值** |

```python
import cv2, requests
cap = cv2.VideoCapture("http://127.0.0.1:8099/stream.mjpg")
while True:
    ok, frame = cap.read()                      # BGR ndarray, 640x480
    st = requests.get("http://127.0.0.1:8099/state.json").json()
    for d in st["detections"]:
        # d = {"cls": "3", "plate": "armor1",
        #      "bbox_xyxy": [...], "bbox_xywh": [...], "center": [...]}
        ...
```

- 相机挂在**云台 pitch 体**上、朝向与炮管轴对齐，并**持续跟踪靶车**，所以目标始终在视野内。
- 类别名就是贴纸号码（`--label` 可改），bbox 由装甲板盒的 8 个角投影取外接矩形得到。
- 落盘数据集：`--save-dir ~/rm-dataset`（每 N 帧存 `frame_XXXXXX.jpg` + 同名 `.json`）。

### 与 `sp_vision_25` 的对接

`sp_vision_25` 的相机输入目前只有 **MindVision / HikRobot 两个 SDK 分支**（`io/camera.cpp`），
两者都绑定自家硬件，**不能直接吃仿真流**。三条可行路线，按投入排序：

1. **当数据源用（零改动，推荐先做）**
   用 `/state.json` 的 bbox 自动标注训练集，或把仿真帧喂给它的**离线检测程序**验证网络召回。
   这条路不需要改 `sp_vision` 一行代码。

2. **虚拟摄像头（推荐做闭环）**
   `v4l2loopback` 建一个虚拟 v4l2 设备 → `rm_stream` 的 MJPEG 写进去 →
   在 `io/camera.cpp` 里加一个约 15 行的 `camera_name: "v4l2"` 分支（`cv::VideoCapture("/dev/videoN")`）。
   这样仿真就成了它的"相机"，可以完整跑闭环。

3. **复刻它的录制格式（离线回放）**
   `tools/recorder.cpp` 录成 `records/<name>.avi`（MJPEG）+ 一个文本日志（时间戳 + 四元数）。
   仿真按同样格式产出即可复用它的离线工具链（注意：仓库里目前没有回放程序，需要自己补一个读入端）。

## 8. 已知取舍与限制

这些是有意为之，不是 bug，但换场景时要知道：

| 项 | 说明 |
|---|---|
| **竖直方向是运动学跟随** | 车按地形高度贴地滑行，不靠接触求解。原因：让盒体以强制速度冲过 ±8 cm 三角网格地形，棱角撞台阶的冲量压不住（实测被弹到 +44 cm 并翻滚）。要做到真正的接触物理需要给车装弹簧-阻尼悬挂模型。 |
| **车身姿态是伺服而非自由物理** | 姿态目标 = 地形法向，用角速度 PD 跟随（`mju_subQuat` 算误差）。直接放开 roll/pitch 在 7 rad/s 自旋下会翻滚。 |
| **`ride_z` 是静态几何量** | 取车体几何最低点，平地与缓坡完全准确；坡度 >15° 时车体按平面贴地、地面是曲面，会有几毫米视觉误差。 |
| **viser 的 LOD 被关闭** | mjviser 把"所有无纹理几何"合并成一个 60 万顶点网格，再按距离抽稀到约 1000 顶点 → 远处装甲板糊成灰块。已用 `--keep-lod` 的反向开关默认关闭。 |
| **`--model simple`** | 内置方块模型，仅用于对照/回归，外观与真实模型无关。 |
| **装甲板 4 块贴纸** | 源模型 4 块板的 7 套槽位贴纸命名不一致（3 块用 `13/23/33`、1 块用单字符 `3`），已统一处理；如需换号码用 `--sticker 2/4/5/B/G/O`。 |
