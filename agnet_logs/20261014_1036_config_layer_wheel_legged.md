## 3. 踩的坑（本轮技术含量最高的部分）

1. **限幅介入 → 位置漂移**：第一版跟踪律是纯前馈（指令解析速度 + 加速度限幅）。
   限幅削掉的那部分速度会被一路积分成位置漂移，轨迹顶到软边界 1.02×A 上，
   现象看起来像「幅度反而变大了」。
2. **只加 P 项也不行**：前馈已把指令加速度解析抵消，误差方程退化成 ë + kp·e = 0 —— 无阻尼振荡器，
   数值误差被放大成持续振荡（默认档就顶到加速度上限）。必须补 kd·ė（kp=25 / kd=10 → ωn=5、ζ=1）。
3. **PD 必须加在加速度上**：加在速度指令上等于给 ė 乘 1/dt（1/0.002 = 500 倍刚度），
   实测 88% 的步饱和、峰加速假象 235 m/s²。改成 a_cmd = a_target(前馈) + kp·e + kd·ė 后干净。
4. **量测坑**：一开始拿 overview 图做 A/B，但靶车同时在平移、距离也在变，固定裁剪窗量出来的位移是垃圾；
   改成「按相机几何把目标投影到像素 + 按深度归一化到同一世界尺度 + 用装甲板上沿（≥6 个暗像素的行）」
   才量出可信的斜率。另外第一版统计把**我方机器人**也框进窗口，质心被拖偏 400 mm。
5. YAML 1.1 的 `mode: off` 会被解析成布尔 False → 加载器里做归一化。

## 5c. 轮腿升降对成绩的影响（探索性，2 种子 × 150 s）

同一策略（产线 RL quality，λ=0.69）、同一基准脚本、同一批种子，背靠背跑「有升降 / 无升降」：

| | 无升降 | 有升降 periodic | 说明 |
|---|---|---|---|
| 发射 / 命中 | 159 / 98 | 156 / 89 | |
| 命中率 | **61.6%** | **57.1%** | −4.5 点 |
| 击杀 | 2 | 2 | 样本太小 |
| 每击杀弹量 | 80 | 78 | 基本持平 |
| TTK(首中) | 111.5 / 78.9 s | 89.0 / 79.5 s | 方向不一致 = 噪声 |
| 仿真帧率 | 30.3 | 30.3 | **可比性前提满足**（存档基线 29.4，差 3%） |

**口径说明**：只有 2 个种子 × 150 s、每臂只打死 2 台车，**只能当趋势看**，不能当基线；
而且这批跑的是**基准脚本场景**（4 段靶型、原地随机甩头占了 3/4 的射击量），
所以命中率绝对值比正式口径（300 s 随机运动、46.5%）高不少，**不要跨口径比。**

结论：轮腿升降对命中率的代价在**几个点**量级（不是几十个点），
真正被打到的是竖直方向的预测 —— 正好是阶段 2（预测）的考题。

**顺带修掉一个会误导人的工具 bug**：`tools/aggregate_bench.py` 把帧率写死成 `frame/300`，
跑 150 s 的快速对照时会把 30.3 FPS 算成 14.7，触发「与对照帧率相差 >10% 不可比」的**假警报**
（差点让一组本来可比的数据被当成不可比）。现在改成用快照里的仿真时间 `t`，
并按新口径重新聚合了两份存档。
